# ls20 — Complete Game Semantics

## Semantic Family: Inventory/Automaton on Finite Graph

## Available Actions: [1, 2, 3, 4]
- ACTION1 = move up (y -= cell_height)
- ACTION2 = move down (y += cell_height)
- ACTION3 = move left (x -= cell_width)
- ACTION4 = move right (x += cell_width)

## Grid
- Camera: 16×16 logical, rendered to 64×64 pixels (scale factor 4)
- Cell size: player sprite is 5×5 pixels, so grid cells are 5×5
- Movement step: 5 pixels in each direction

## State Type
```
(player_x, player_y, shape_idx, color_idx, rotation_idx, goals_collected: Set)
```

- `shape_idx`: 0-5 (6 shapes in `ijessuuig` list)
- `color_idx`: 0-3 (4 colors: [12, 9, 14, 8] = [epqvqkpffo, jninpsotet, bejggpjowv, tqogkgimes])
- `rotation_idx`: 0-3 (rotations: [0°, 90°, 180°, 270°])
- `goals_collected`: bitmask of which goals have been visited with correct state

## Transition Function

On ACTION{1,2,3,4}:
1. Compute new position: (player_x + dx*5, player_y + dy*5)
   - ACTION1: dy=-1, ACTION2: dy=+1, ACTION3: dx=-1, ACTION4: dx=+1
2. Check collision at new position (`txnfzvzetn`):
   - If wall (`ihdgageizm`): movement blocked, player stays
   - If goal (`rjlbuycveu`): check if player state matches goal requirements
     - If match: goal collected, sprites removed
     - If no match: blocked (error animation, counts as failed attempt)
   - If shape changer (`ttfwljgohq`): shape_idx = (shape_idx + 1) % 6
   - If color changer (`soyhouuebz`): color_idx = (color_idx + 1) % 4
   - If rotation changer (`rhsxkxzdjz`): rotation_idx = (rotation_idx + 1) % 4
   - If step refill (`npxgalaybz`): step counter reset to max
3. If not blocked: player moves to new position
4. Patrolling walls (`dboxixicic`) step along their paths
5. Pushable walls (`twkzhcfelv`) check if player collides and push if possible
6. Step counter decrements by `StepsDecrement` (default 2, some levels 1)
7. Check win condition

## Win Condition (pbznecvnfr)
For each goal i:
- Player position == goal i position AND
- `bejndxqqzf(i)`: shape_idx == goal_shape[i] AND color_idx == goal_color[i] AND rotation_idx == goal_rotation[i]
- Mark goal as collected
ALL goals must be collected → next_level()

## Lose Condition
- Step counter reaches 0 → lose one of 3 attempts
- On lose: player resets to start position, state resets, step counter resets
- 3 attempts total per level (aqygnziho = 3)
- After 3 failed attempts → game over

## NF_G — The Normalizer

From the 64×64 grid observation:

1. **Read player position**: Find the 5×5 block matching the player sprite pattern (colors 12+9 or current color pattern). Position = (x, y).

2. **Read player state**: The display sprite at bottom-left shows current shape/color/rotation. OR: track from initial state + actions taken (observation history).

3. **Read goal positions**: Find 5×5 blocks of color 5 (rjlbuycveu). Nearby kvynsvxbpi sprites show required shape.

4. **Read goal requirements**: GoalColor, GoalRotation, GoalShape from the kvynsvxbpi display.

5. **Read modifier positions**: Find ttfwljgohq (shape changer), soyhouuebz (color changer), rhsxkxzdjz (rotation changer) by their pixel patterns.

6. **Read wall layout**: All color-4 5×5 blocks are walls.

7. **Compute tension**:
   - For each uncollected goal: what modifiers does the player need to hit first?
   - shape_deficit = (goal_shape - current_shape) mod 6
   - color_deficit = (goal_color_idx - current_color_idx) mod 4
   - rotation_deficit = (goal_rotation_idx - current_rotation_idx) mod 4
   - Next target = nearest required modifier, or goal if state matches

8. **Compute action**: Direction toward next target. If target is up → ACTION1. Down → ACTION2. Left → ACTION3. Right → ACTION4. Manhattan distance determines the primary tension channel.

## Semantic Class Instance

```
State = (Nat × Nat × Fin 6 × Fin 4 × Fin 4 × BitVec n_goals)
Action = Fin 4 (directions)
step = move + collision + modifier_update
solved = all goals collected
tension = Σ (deficit_per_goal + distance_per_goal)
NF_G = read grid → identify state → compute deficit → determine direction
```
